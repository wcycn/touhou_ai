# 东方红魔乡自动通关项目路线

当前基线已经在真实游戏中走通：

```text
Wine启动 → 窗口定位 → 屏幕捕获 → YOLO检测
→ 规则决策 → 焦点守护 → PyAutoGUI输入 → 人物移动
```

这说明项目已经是可运行的MVP。后续目标不是盲目增加“AI”名词，而是把每一层变得
可观测、可测试、可比较，最终提高生存时间和通关率。

## P0：运行记录与离线回放（已完成基础版本）

目标：每次失败后能够回答“哪一帧看错了、做了什么、为什么做”。

记录内容：

- 会话开始/结束时间、运行参数、模型路径和截图区域
- 每帧的检测框、类别、置信度
- 自机坐标、敌弹/敌人/道具数量、危险度
- AI计划和实际执行的移动、射击、炸弹
- 固定帧率抽样保存的原始游戏画面
- 总帧数、检测总数、自机检出率、最高危险度、动作分布
- 正常结束、用户停止、游戏退出或异常等结束原因

验收标准：

- 记录功能不能改变控制节奏或发送额外按键
- 中途异常退出后，已经写入的JSONL仍然可读
- GUI能列出会话、显示摘要、浏览抽样帧
- 可以生成便于比较的Markdown/JSON报告

## P1：边界与动作稳定性（已实现，待实战验收）

目标：避免人物持续撞边、方向抖动和无意义的频繁松按。

- 根据真实自机坐标建立左右/上下安全边界
- 将“目标方向”和“当前按键状态”分开，只在状态变化时发送事件
- 为移动动作设置最短持续时间和冷却时间
- 统计每秒方向切换次数，作为抖动指标
- 任何异常退出都必须释放所有控制键

验收标准：连续运行时不贴死边缘，方向切换频率明显下降。

## P2：自机跟踪与短时漏检恢复（已实现，待实战验收）

目标：模型偶尔漏掉 `character` 时，决策不立刻退回错误的画面底部中心。

- 保存最近可靠的自机坐标、速度和置信度
- 使用短时间卡尔曼滤波或指数平滑预测位置
- 超过失效时间后停止危险动作，而不是继续猜测
- 在回放报告中标记连续漏检区间

验收标准：短时漏检不引起突发反向移动，长时漏检能够安全停控。

## P3：弹幕轨迹和碰撞预测（已实现基础版本，待录像校准）

目标：从“躲当前最近的弹”升级为“躲未来会撞上的弹”。

- 跨帧匹配敌弹并估计速度
- 计算未来若干帧的碰撞时间（TTC）
- 在候选移动方向上预测风险代价
- 同时考虑屏幕边界、敌弹密度和移动惯性
- 在回放中画出预测轨迹与选择原因

验收标准：同一段录像上的预测碰撞数和实际危险情况基本一致。

## P4：游戏状态机（已实现安全门控，具体菜单待数据）

目标：区分战斗、菜单、暂停、死亡、续关和关卡结束，避免在错误场景乱按。

- 标题/主菜单状态
- 角色与难度选择
- 正常战斗
- 暂停
- Miss/残机重生
- Game Over/续关
- 关卡完成/结局

验收标准：只有“正常战斗”状态允许移动射击，其他状态执行明确、有限的导航动作。

## P5：模型评估与数据闭环（工具已实现，等待人工标注）

目标：量化YOLO模型，而不是仅凭肉眼判断。

- 从会话中挑选高误检、漏检和死亡前帧
- 建立小型人工标注验证集
- 分类别统计Precision、Recall和混淆情况
- 调整置信度阈值并比较生存时间
- 必要时再补数据、重训模型

验收标准：模型或阈值修改有可重复的离线指标和实战指标支持。

## P6：学习型策略（最后考虑）

只有前面的截图、检测、状态和输入链路稳定后，才考虑：

- 从人工/规则轨迹进行模仿学习
- 用回放数据训练风险或价值模型
- 在可控模拟环境中尝试强化学习

不建议直接在当前真实游戏闭环上训练强化学习，因为窗口、检测和输入误差会混在一起，
很难判断策略失败的原因。
